# Human resources

The HR workspace is `/workspace/hr`. HR Manager and HR Executive roles select
their corresponding dashboard automatically; `?view=manager` or
`?view=executive` changes presentation while API permissions remain authoritative.

The workspace manages attendance, leave types/balances/requests, shifts,
assignments, holidays, salary structures, payslips, onboarding/offboarding,
tasks/templates, review cycles/reviews/goals, jobs, candidates, and interviews.
Employee and department links use their organization modules. Documents use
the existing document workspace. Reports export actual headcount data.

Recruitment proceeds from applied to shortlisted, interviewing, offered, and
hired. Rejection and withdrawal close an application. An offer requires a
completed interview with feedback. Hiring requires an employee code and joining
date; it creates the employee and onboarding process (including configured task
templates) in one transaction. No login account or email is automatically sent.
Interview scheduling rejects overlaps for the same interviewer.

An active subscription must include HR and organization HR enablement must allow
access. All HR endpoints also require domain permissions and scope reads and
submitted relationships to the selected organization. HR Executive receives
view/create/update permissions. HR Manager additionally receives deletion,
approval, payroll processing/payment recording, and export permissions.

Apply `hr_recruitment` and `rbac` migrations to each deployed database. RBAC
migration `0006` adds workflow grants to existing built-in HR roles without
replacing custom role assignments. New installations use the permission and
role seed catalog. Migration `0007` preserves the existing HR capabilities of
organization owners and administrators. Processed and paid payslips cannot be
edited or deleted; invalid payroll totals return validation errors.

Validation from `backend`:

```powershell
..\venv\Scripts\python.exe -m pytest apps/hr -q --no-cov -p no:cacheprovider
..\venv\Scripts\python.exe -m mypy --config-file scripts/datavionos_hr_mypy.ini apps/hr
..\venv\Scripts\python.exe -m ruff check apps/hr
```

From `frontend`: `npm.cmd run typecheck` and `npm.cmd run test:e2e:hr`.
The latter checks browser states using API fixtures. For real browser/API
integration, start the frontend on localhost:3000 and run from `backend`:

```powershell
$env:DATAVION_HR_LIVE = '1'
..\venv\Scripts\python.exe -m pytest apps/hr/tests/test_live_browser.py -q --no-cov -p no:cacheprovider
```

This creates a disposable test organization, subscription, and seeded HR Manager
in the pytest database. Playwright relays HTTP requests to Django's live server;
responses are generated by the real auth, bootstrap, and domain APIs. The test
URL configuration mounts these production endpoints independently of unrelated
clinical modules. Backend workflow tests also verify organization isolation,
leave balance reversals, payroll totals, lifecycle tasks, and review transitions.
